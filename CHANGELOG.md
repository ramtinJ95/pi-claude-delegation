# Changelog

The scoped `@ramtinj95/pi-claude-delegation` package starts at 0.1.0. Entries
for `pi-claude-bridge` 0.7.0 and earlier are retained below as inherited
upstream history under the MIT license.

## 0.1.5 — 2026-09-05

- **Fix: query completion and prompt cleanup** — Require an authoritative result before accepting isolated compaction/branch summaries, reuse the delegation EOF invariant, avoid launching already-cancelled summaries, and reject queued prompt acknowledgements when their consumer closes.
- **Fix: bounded, cancellable reviewer capture** — Stream bounded Git output under a shared 30-second capture deadline, forward launch cancellation, distinguish subprocess failures from normal diff exit codes, and continue validating omitted files without retaining their output. Oversized Git metadata fails visibly rather than silently skipping files.
- **Refactor: coalesced delegation progress** — Share 100ms latest-value publication across foreground and background calls, flush pending background activity before settlement, and preserve unchanged manager-record identities so overlay Markdown caches survive unrelated updates.
- **Refactor: explicit delegation ownership** — Extract shared-session synchronization, isolated summaries, foreground execution, spawn registration, and result formatting from the entry point; consolidate query-input assembly and permission annotations while preserving provider/delegation separation and foreground/background session semantics.

## 0.1.4 — 2026-09-01

- **Bump: require Claude Fable 5.1** — Upgrade the Claude Agent SDK from 0.2.141 to 0.3.257 so `DelegateToClaude` and `SpawnClaudeAgent` use a Claude Code runtime new enough to launch `claude-fable-5-1`. Replace Fable 5 in the provider catalog, make the `fable` shortcut select Fable 5.1, and force stale `claude-fable-5` requests onto 5.1 so this package can no longer invoke Fable 5.

## 0.1.3 — 2026-08-26

- **Refactor: retain the latest delegation activity** — DelegateToClaude and spawned-agent details now keep only the latest 10 tool calls and the latest 4,000 characters of emitted thinking, with explicit counts for omitted earlier activity.

## 0.1.2 — 2026-08-22

- **Add: live delegated-context usage** — Track top-level Claude Code `message_start`/`message_delta` usage separately from cumulative run billing, show live context occupancy while the served window is pending, and add an authoritative context-window percentage once the terminal SDK result reports it. Nested-agent context remains excluded so the overlay and live widget do not mislabel subagent usage as the parent session.

## 0.1.1 — 2026-08-22

- **Refactor: concise Claude delegation tool schemas** — Shorten the model-facing tool and parameter descriptions for `DelegateToClaude` and `SpawnClaudeAgent` while retaining capability defaults, isolation behavior, background delivery, and full-mode safety constraints.

## 0.1.0 — 2026-08-22

- **Add: independent package and runtime namespace** — Publish the fork as `@ramtinj95/pi-claude-delegation`; register the provider as `claude-delegation`; read `claude-delegation.json` with a `delegation` tool-config block; and expose the blocking compatibility path as `DelegateToClaude` while retaining `SpawnClaudeAgent`. Historical `claude-bridge` transcript thinking remains replayable, and the process-global checkout lease deliberately retains its legacy coordination key so an unsettled pre-migration worker still blocks a new writer. The release preserves upstream attribution and changelog history. Typecheck, unit, and package validation are clean, but the Phase 3d manual dogfood checks for reload-time worker termination and checkout-write ownership remain explicitly unrecorded.
- **Bump: MCP SDK and audited transitive dependencies** — Raise `@modelcontextprotocol/sdk` to `^1.30.0` and refresh the lockfile within declared ranges, clearing the production dependency audit before publication.

- **Refactor: align SpawnClaudeAgent with AskClaude capability modes (Phase 3d, breaking)** — Replace the public `profile: explorer | reviewer | worker` input with the explicit `mode: none | read | full` capability contract already used by AskClaude. None derives an honest no-tools advisor, read derives the structurally bounded explorer, optional `review: { base?: string }` specializes read mode into a reviewer with the existing frozen launch diff, and full derives the existing checkout-writing worker. Full mode keeps the `user_requested: true` assertion, `allowFullMode` lockout, process-global checkout lease, cancellation hard-close, and foreground/background safety rules; supplying the assertion outside full mode or combining review with none/full fails visibly. Foreground extraction and inline call rendering remain compatible with restored profile-based calls, while current call rows, background results, widgets, completion entries, status lines, and the unified overlay expose capability mode alongside the derived role label. An impossible missing-settlement state after worker spawn now fails closed with checkout ownership still held rather than releasing the lease under an unconfirmed writer. SpawnClaudeAgent now covers AskClaude's no-access capability as well as its read/full modes without changing AskClaude itself.
- **Add: SpawnClaudeAgent worker profile and selectable execution modes (Phase 3c)** — SpawnClaudeAgent gains a full-capability `worker` profile and an `execution: "foreground" | "background"` parameter (default `background`, preserving the shipped contract). The worker resolves through the existing `full` capability policy (Claude Code preset with the same disallowed interactive/lifecycle tools as AskClaude full mode) with the permission policy taken from the configured `askClaude.permissionMode` (default `auto`; bypass is never hard-coded), and its role prompt makes the contract explicit: it edits the current checkout as the only writer and must not commit, push, open PRs, change branches, or perform destructive cleanup unless the task explicitly authorizes it. Worker dispatch also requires `user_requested: true`, an explicit structured assertion reserved for user-requested implementation delegation; malformed profile/execution values fail visibly instead of escaping through unchecked casts. The `askClaude.allowFullMode: false` lockout removes the worker profile from the schema and rejects worker calls at dispatch; explorer/reviewer remain structurally read-only. Foreground execution blocks the tool call and returns the bounded result directly through the same shared foreground implementation as AskClaude — one delegation runner, retained/redacted snapshot, throttled live tool-row updates, rich renderer, error/cancellation semantics, and live overlay slot — extracted from the AskClaude registration into one `executeForegroundDelegation` adapter that AskClaude now wraps as a compatibility tool (its schema, mode/isolation defaults, name/label/description/allowFullMode/appendSkills configuration, and rendering are unchanged). Foreground calls default to fresh isolated sessions and support `isolated: false` with the exact AskClaude shared-session resume behavior; `execution: "background"` with `isolated: false` is rejected visibly instead of silently ignored. Reviewer launch-diff capture and base validation run identically in both execution modes, agents launch from Pi's execute-context cwd (AskClaude and delegation queries now use the session cwd rather than `process.cwd()`), and background jobs keep the existing manager, job-ID result, widget, cancellation, shutdown/persistence, one-job limit, and next-turn delivery path — with background job policy now resolved from the same configured `askClaude.permissionMode`. One atomic process-global checkout lease covers background workers, foreground workers, and AskClaude full mode, rejecting concurrent Claude writers even across extension reload; abandonment does not release the lease before the executor really settles, and abort immediately hard-closes the SDK query transport as well as requesting cooperative interrupt so a wedged request cannot continue editing behind a dismissed warning. Background worker results and the widget retain their explicit single-writer warning; a git-worktree lifecycle is deliberately deferred. The unified Claude Sessions overlay includes foreground SpawnClaudeAgent calls as foreground Claude records labelled `SpawnClaudeAgent <profile> (foreground)` with a Task body section, read from the same persisted tool-call/result pairs and live slot as AskClaude records (no new persistence format) and restored the same way, while `/askclaude-details [n]` keeps counting actual AskClaude compatibility calls only.
- **Add: unified Claude Sessions overlay across AskClaude calls and background jobs** — the AskClaude-only details overlay is now one "Claude Sessions" overlay over a single flat chronological list of both kinds, with clear kind/profile/status labels and `←`/`→` navigation across the merged list. `Ctrl+N` toggles it, focusing a running background job first (pinned so live updates cannot steal the selection) and otherwise the chronologically latest record; `/claude-details [n]` is the canonical command with an optional 1-based index into the merged list; `/askclaude-details [n]` stays as a compatibility alias that opens the same unfiltered overlay focused on the latest AskClaude record, resolving `n` among AskClaude calls only before mapping it to the merged list. `/claude-jobs` with no arguments now opens the overlay focused on the running (else latest) background job in the TUI, says so honestly when the session has none, and keeps its textual status listing outside the TUI; `/claude-jobs cancel [job-id]` is unchanged, and the live widget hint now mentions `Ctrl+N` details alongside the cancel guidance. Background records reuse the persisted bounded `claude-background-job` completion entries — validated by the same exported guard the transcript renderer uses, so malformed or forward-incompatible entries degrade to a visible placeholder instead of throwing — merged with the job manager's records and deduplicated by job ID (the persisted entry wins for settled jobs; the manager supplies running state and is the terminal fallback when persistence is absent). Both kinds render through the same retained/redacted sections (Prompt/Task, Thinking, Tools, Timeline, Response, Diagnostics); background headers show only background Claude facts (profile, status, runtime/requested model, thinking, permission/managed policy, Claude session/cwd, usage, elapsed/duration, job ID, and diff source when applicable). One overlay owner remains: the overlay subscribes to both the AskClaude live slot and the job manager while open, releases both on dispose, keeps the parsed-body cache for a pinned immutable record, and normalizes AskClaude ISO timestamps and background epoch timestamps with deterministic branch order as the fallback for missing timestamps. No new raw or unbounded data enters the overlay.
- **Add: SpawnClaudeAgent background jobs with live widget and completion delivery** — a first-class Pi tool (registered under the same `askClaude.enabled` opt-in) starts one independent background Claude Code agent per Pi session and returns immediately with a stable job ID. Jobs run through the same provider-independent delegation runner, pure policy/options boundary, and retained/redacted snapshot as AskClaude, always in a fresh isolated Claude session with AskClaude-consistent model/thinking parameters. The `explorer` and `reviewer` profiles both resolve to the explicit read inventory (Read, Glob, Grep, WebFetch, WebSearch — no Bash, mutation, or nested Agent) with distinct role prompts; the reviewer additionally receives an immutable repository status/diff artifact the extension captures at launch, with an optional merge-base comparison ref for branch/PR review, tracked-and-untracked working-tree capture, named bounds (40k diff / 4k status) with visible truncation and best-effort redaction, a recorded source, and clear failures for non-git directories or invalid refs instead of a misleading empty diff. The session-scoped job manager owns per-job AbortControllers and explicit first-wins terminal states (succeeded, failed, cancelled, abandoned): a second concurrent spawn is promoted to a visible error result rather than queued (and skips reviewer diff capture entirely), and cancelling the initiating tool call before the job ID is returned prevents the launch — once spawned, the job's own controller owns its lifecycle. Session shutdown/switch aborts running jobs and, through async handlers Pi 0.84.2 awaits, waits up to a named 2-second grace for the runner to confirm settlement; a job that settles in time keeps its genuine terminal state (usually cancelled) and only jobs still unconfirmed after the grace are recorded as abandoned. Job IDs carry a collision-resistant random per-runtime prefix plus a monotonic counter (e.g. `claude-job-3f9c2d1a7b4e-1`), so ID collisions across extension reloads are overwhelmingly unlikely and a session reset never reuses an ID within one manager. When the delegation runner reports its observed permission mode and non-sensitive managed-policy summary, the terminal job record keeps those bounded facts alongside the retained snapshot; jobs whose runner never produced them (failure, abandonment) record nothing rather than borrowing Pi session state. Records are bounded and in-memory only; there is still no persistence across Pi sessions and no model-callable status/result/cancel tools. On top of that core, the extension now renders and delivers the jobs through Pi 0.84.2's native surfaces: a sticky live widget above the editor shows only Claude-job facts (job ID, profile, requested/runtime model, requested thinking, status, current action, elapsed time, runtime permission mode, denial count, and usage once reported) in at most three width-truncated lines, repainting on manager transitions plus a once-per-second tick and disappearing on every terminal, shutdown, or reset transition; `/claude-jobs` lists this session's bounded job records for humans and `/claude-jobs cancel [job-id]` cancels through the manager's existing contract, reporting unknown and already-terminal jobs honestly instead of pretending; and each job's terminal state is delivered exactly once — one bounded, redacted, session-persisted TUI-only custom entry (`claude-background-job`) whose registered renderer shows collapsed/expanded reviewable details (task, actions, aggregate tool line, usage, permission/managed-policy state, response) including after session restore, plus one bounded model-visible custom message sent with Pi 0.84.2's `sendMessage(..., { triggerTurn: false, deliverAs: "nextTurn" })`, which queues alongside the next user prompt and never interrupts or triggers a main-agent turn. Succeeded, failed, cancelled, and abandoned outcomes stay explicit — a success with no output text says so rather than reading as a blank answer, and policy annotations survive a capped answer. The manager emits one first-wins `settled` transition per job (which is what makes delivery exactly-once) and flags settlements that happen inside shutdown/reset, so a session being torn down or replaced never receives a late completion entry, message, or widget update; the pending next-turn message is in-memory Pi state and is lost if Pi exits before the next prompt.
- **Fix: pre-start delegation cancellation uses the normal terminal path** — a signal already aborted when the shared delegation runner starts now publishes and returns a cancelled snapshot without launching Claude Code, rather than throwing a generic error. This makes queued background-job cancellation safe to build on.
- **Refactor: extract the Claude-native delegation engine and expose rich AskClaude observability** — AskClaude now builds Agent SDK options through a pure boundary where isolation and session resume are mutually exclusive by type, and runs through a provider-independent lifecycle that normalizes partial streamed text, emitted thinking, tool starts/inputs/progress/results with their subagent parent, usage, permission state, retries, rate limits, session metadata, assistant errors, and SDK frames it does not handle. Its Pi 0.84 tool row streams the same retained snapshot used by the final compact/expanded themed view; the expanded row keeps Claude-only metadata, the prompt, emitted thinking, usage, policy state, and the authoritative response, plus a grouped action summary and one aggregate tool-status line whose total stays honest about tools whose details were not retained, while per-tool inputs/outputs, durations, nesting, and the retained timeline appear only in the details overlay. Model output, thinking, tool fields and timeline are bounded with visible truncation, and persisted display details receive best-effort credential redaction. The model-facing result spends one total budget in priority order, so a permission override or denial is never the annotation that falls off the end of a capped answer. Cancellation reaches the model as an explicit error result that keeps whatever answer and actions arrived first, and a stream that ends without an authoritative result fails instead of reporting an empty success. A Pi-native details overlay (`/askclaude-details`, `Ctrl+N`) deep-inspects any AskClaude call read from the current session branch — including after session resume — with a pinned Claude-only metadata header (runtime model, tokens/cost/turns, Claude session ID and cwd, runtime permission mode, status, capability, isolation, thinking; `unavailable` rather than any Pi fallback), a scrollable body (full original prompt from the persisted tool-call arguments, emitted thinking, retained tools/timeline, authoritative response under the same retained limits), line/page/home/end/section navigation, previous/next call switching, and live updates for the running call from the same bounded record the tool row streams.
- **Refactor: safe Claude delegation policy defaults (breaking)** — AskClaude now enforces `read` and `none` with explicit tool inventories, excludes nested Agent from read mode, defaults to fresh isolated conversations, and independently resolves configurable Claude Code permission modes. Provider, compaction, and delegation queries default to `auto`; runtime overrides, denials, and non-sensitive managed-policy constraints are surfaced without installing a host-side permission override or claiming more sandbox detail than the SDK exposes.
- **Bump: establish the Pi 0.84.2 baseline** — require Pi 0.84.2 and Node.js 22.19, pin matching Pi development packages, run integration harnesses against that local CLI, add an offline extension-load/provider-registration smoke test, record the Agent SDK and bundled Claude Code versions in test output, and explicitly characterize the lifecycle-hook adapter gap without fabricating request or response data.
- **Fix: AskClaude descriptions reflect configured defaults** — model-facing parameter text, the top-level tool description, and TUI tags now report the effective `defaultMode` and `defaultIsolated` values instead of hard-coding read/shared defaults. `allowFullMode: false` also prevents a configured full default from bypassing the lockout when `mode` is omitted, and malformed JSON mode, full-mode, and isolation values resolve to safe package defaults.
- **Fix: better isolate AskClaude tool (issue #59)** — AskClaude children no longer inherit the user's `~/.claude` `CLAUDE.md` files or skill listing, and now always get Claude Code's system prompt preset instead of only when pi-side skills exist. Thanks @JAtkinsonKO.
- **Fix: Bogus debug message about "record count mismatch" after switching providers** — the post-rebuild integrity check did not take `@file` expansion into account when switching providers.

## 0.7.0 — 2026-08-08

- **BREAKING: AskClaude tool now off by default** — If you want to continue using the AskClaude tool, set `askClaude.enabled` to `true` in your config (see README.md).
- **New: mid-turn steering actually works (issue #39)** — a steer sent while a tool was running used to be stashed and replayed as a follow-up after Claude's whole turn finished. The prompt is now a long-lived streaming generator and the steer is written to CC's stdin (`priority: "next"`) before the tool result is released, so CC drains it at that tool boundary and acts on it in the same turn.
- **Fix: system prompt loading** — Claude Code now receives the same global and hierarchical `AGENTS.md` / `CLAUDE.md` files that Pi loads. Config settings`provider.appendSystemPrompt` / `provider.settingSources` are no longer needed and have been removed gone). Improved compatibility with for children agent (i.e. subagents) and for other extensions that modify the system prompt. Unhandled system prompt configurations should fail loudly rather than silently discarding instructions.
- **Fix: branch summarization ran through the live provider** — rewinding or forking with "summarize" runs through the *agent's* stream function, so unlike `/compact` the request reached this provider and the live Claude Code session rather than an isolated subprocess. The bridge now takes over `session_before_tree` the way it already took over `session_before_compact`.
- **Fix: `@file` mentions were lost when a session was rebuilt** — Claude Code expands an at-mention itself (unlike pi) and stores the file's contents as an `attachment` record in its own session file; pi never sees it, so a rebuild kept the prompt text and silently dropped the file the model was reasoning about. Expansions are now carried across. Requires cc-session-io `^0.4.0`.
- **Fix: images dropped from prompts and rebuilt sessions (issue #34)** — an image followed by a trailing text preview lost the image, and tool results carrying images were flattened to text whenever the bridge rewrote pi's history into a Claude Code session. Images survive both paths now.
- **Fix: session rebuilds could corrupt turn structure** — pi records one message per tool result, and `repairToolPairing` (applied inside `Session.importMessages`, so unavoidable) only pairs results sharing the user message right after their assistant message, so tool results past the first can become `[no tool result recorded]`; a turn's results are now collected into one message placed directly after its assistant message. Minor: a turn aborted before anything streamed was rebuilt as `[incompatible content omitted]` potentially misleading the agent into thinking it is missing something. Empty turns are dropped now, while genuinely filtered content keeps its slot and label. Rebuilds also incorrectly wrote pi's bare model id instead of the resolved CLI id, dropping the `[1m]` suffix (issue #42; minor metadata fix only, since `--model` was already correct).
- **Fix: errored turns could report as a successful stop** — CC flags failures with `is_error` on a result whose subtype is still `"success"`, so the bridge duplicated the error text and finalized normally (issue #43); failed results now end the turn with `stopReason: "error"`, and the compact-summary path no longer accepts an errored result. Separately, a turn that ended on a tool call has its pi stream closed, and the guard suppressing content events for a closed stream also swallowed the `result` message, so a 429 or overload mid-tool set no `stopReason` and logged nothing (part of issue #35). The no-event stream watchdog idea in #35 has not been addressed.
- **Fix: a reentrant subagent could disturb the parent's session** — the shared session cursor was written from whichever context delivered tool results, so a background subagent dragged the parent's cursor backwards and cost its next turn a full rebuild and a flushed prompt cache. Removal from the active-context set is now guarded like the cleanups beside it, and an orphaned tool result no longer resets the live top-level context's turn state.
- **Fix: bridge could deadlock on a tool name Claude can't call** — Claude sometimes called `bash` instead of `mcp__custom-tools__bash`; CC rejected it with "No such tool available" and retried under a fresh tool_use id, but the bridge had already run the rejected call, so the retry's MCP handler waited on a result that never came. Calls for anything the bridge does not serve over MCP are now ignored. Rebuilt transcripts contributed to this by sometimes naming tools as `Bash`/`Read`/`Edit`/`Write` in past calls; those names now stay in the `mcp__custom-tools__` namespace.
- **Fix: nested tool schemas flattened (issue #44)** — converting pi schemas to Zod collapsed nested objects and dropped `anyOf`/`const`, so Claude saw only the top level of tools like `edit` and `subagent`. The MCP server now serves pi's JSON Schema verbatim.
- **Fix: tool results paired by call order** — MCP handlers took their `toolCallId` from a positional cursor, so a call arriving out of order silently paired its result with the wrong tool call. Now pairs by Claude's `_meta["claudecode/toolUseId"]` and fails loudly if it is absent.
- **Fix: Claude Code could write memory from bridge turns** — provider and AskClaude queries now disable auto-memory through the SDK; set `provider.autoMemoryEnabled` to `true` to opt in if you actually want it. Isolated compaction queries always disable it.
- **Tests: suites now drive the real code** — `tests/lib/record-sdk-streams.mjs` captures verbatim SDK streams (scrubbed, and refusing any fixture the username survived) for `tests/unit-stream-replay.mjs`, replacing hand-written messages that missed the `system/status` and `rate_limit_event` frames a real stream carries. `tests/int-shutdown-kills-cc.mjs` pins that a pi shutdown and a user abort each reap the Claude Code subprocess with a tool call in flight.
- **Tests: correctness audit tooling** — `diag/audit-{transcripts,cache,warnings}.mjs` scan session transcripts and the bridge log for silent data loss, prefix-cache breaks and stranded tool handlers, gated on `--since`; `diag/replay-write-path.mjs` replays any pi session through the rebuild. `tests/int-cc-contracts.mjs` pins the undocumented Claude Code behavior the bridge depends on against the installed SDK, and `tests/unit-convert-determinism.mjs` pins that a rebuild is deterministic and extends the previous transcript rather than rewriting it.
- **Internal: trim redundant dependencies** — pi bundles typebox and its extension loader always aliases the import to that copy, so shipping our own only made consumers install a redundant one that pi ignores. Now `peerDependencies: "*"` plus a devDependency for typechecking, as pi's packaging docs require; dev peers track pi 0.83.0. `@anthropic-ai/sdk` moves to devDependencies for the same reason — it is only ever imported for types.

## 0.4.0 — 2026-05-04

- **Fix: Opus 4.7 + xhigh sent wrong effort to SDK** — pi-ai 0.72 ships per-model `thinkingLevelMap` overrides (e.g. `claude-opus-4-7` declares `xhigh→xhigh`, not `xhigh→max`), but our hardcoded `REASONING_TO_EFFORT` table ignored them. Effort lookup now consults `model.thinkingLevelMap` first, falls back to the table for older pi-ai or unmapped levels. Forwarded `thinkingLevelMap` through `buildModels` projection.
- **Fix: zero out model cost in `buildModels`** — per-token pricing in the footer was wrong because models inherited pi-ai's non-zero cost fields, which pi then multiplied by the huge token counts from the SDK. Now explicitly zeroed so pi's footer shows no cost.
- **Use `tools: []` instead of `disallowedTools` blocklist** — switch from blocking specific tools to explicitly passing an empty tools list, preventing any new default tools from silently leaking into bridge sessions.
- **Disable CC-side autocompact (`DISABLE_AUTO_COMPACT=1`)** — pi already owns context management and propagates its own `/compact` to CC. Letting CC autocompact too double-flushed the prompt cache and raced pi's threshold; manual `/compact` in CC is unaffected.
- **Fix: pi `/compact` no longer triggers CC autocompact-thrashing (issue #8)** — pi's compaction shrinks its messages array, but `syncSharedSession`'s REUSE check (`slice(cursor)`) silently returned `[]`, so the bridge kept `--resume`ing the pre-compact CC session JSONL. Over long sessions CC's own autocompact then refilled within 3 turns and tripped its anti-thrashing guard. Now subscribes to pi's `session_compact` event and forces the next sync down the REBUILD path so CC sees the post-compact history. Also subscribes to `session_tree` (branch nav has the same shape).
- **Refactor: split `needsRebuild` into `needsRebuild` + `forceRotate`** — only the abort case needs UUID rotation (to dodge late writes from the dying CC subprocess). Compact/tree now rebuild in place, preserving the sessionId and not leaking orphan JSONL files into `~/.claude/projects/`.
- **Block user-installed MCP servers from leaking into bridge sessions** — pass `--strict-mcp-config` unconditionally and set `ENABLE_CLAUDEAI_MCP_SERVERS=0` in the spawned CC env, suppressing both filesystem (`~/.claude.json`, `.mcp.json`) and claude.ai cloud MCP servers. Override with `provider.strictMcpConfig: false`.
- **Consolidate config** — SDK plumbing (`appendSystemPrompt`, `settingSources`, `strictMcpConfig`) moved from `~/.pi/agent/settings.json` (`claudeAgentSdkProvider` block) to a `provider` block in `~/.pi/agent/claude-bridge.json`. Old location no longer read. Drop deprecated, unsafe `maxHistoryMessages`.
- **Bump deps** — `@anthropic-ai/claude-agent-sdk` → ^0.2.126; migrate to TypeBox 1.x (new import paths per pi-mono 0.69); pi devDeps → ^0.72.1. Extract `registerTool` schemas to const with explicit `<typeof params>` generic to avoid TS2589 deep-instantiation under TypeBox 1.x.
- **Internal: move sources into `src/`** — `index.ts` and the extracted modules now live under `src/`; screenshots under `assets/`. `pi.extensions` and published `files` updated accordingly.

## 0.3.1 — 2026-04-18

- **Fix: empty thinking blocks on Opus 4.7** — Opus 4.7 silently changed default `thinking.display` from `"summarized"` to `"omitted"`, so streams emitted `thinking_start` + `signature_delta` with zero `thinking_delta` events, leaving `ThinkingBlock.thinking == ""`.
